# Atlas Labs W6

## Scope boundary

W6 adds a private, no-index Labs review at `/internal/atlas-labs` using the approved Kaduna identity for Labs, open source, APIs, plugins, and experiments. It does not change `/open-source`, the homepage, public Studio, or public navigation. The route is absent from public links, blocked by `/internal/` robots policy, and carries `noindex`, `nofollow`, `noarchive`, and `nosnippet` metadata.

## Experience

Labs is a working engineering yard, not a generic project-card grid. Rail and route logic connect a five-project evidence register, a six-stage problem-to-maintenance route, explicit prototype states, contribution guidance, limitations, related routes, and a project discussion action. The scene and interface use testing, assembly, documentation, versioning, handoff, and repair as the visual and motion vocabulary.

`ExperimentRegistry` is an accessible workbench: one selected project receives a full evidence panel, while all five projects remain available in a complete textual equivalent. Roving tab focus supports Arrow, Home, and End keys. The presentation makes repository evidence inspectable without implying adoption, popularity, institutional use, or guaranteed support.

## Components and state orientation

`LabsReview` composes `LabsArrival`, `ExperimentRegistry`, `OpenSourceWorkbench`, `PrototypeStatus`, and `LabsReviewStatus`. `AtlasStateMarker` keeps “Labs” explicit while adding “Kaduna State / Labs District” and a return to `/atlas`. The transition system remains contextual and does not impose the Labs layout on later states.

## Candidate artwork

`ILL-0060` is a fictional contemporary Kaduna engineering-yard candidate. It is not a real laboratory, client project, institutional endorsement, government facility, or team-size claim. Separate desktop and mobile masters were generated; runtime loads only responsive WebP derivatives. Focal points, safe zones, candidate status, meaningful alternative text, and explicit access gating are in the typed registry.

## Motion and reduced motion

Motion is finite and route-based: test, assemble, connect, hand off, release. Tab state changes occur only on visitor input. There are no continuously moving particles, glowing systems, floating screens, scroll hijacking, or new animation dependencies. Reduced motion preserves all project records, releases, limitations, route stages, states, and actions while removing finite line/reveal animation.

## Responsive and accessibility decisions

Desktop places the evidence panel in the artwork’s right-side safe zone and lets the register read as a technical workbench. Mobile uses separately authored vertical art and prioritises identity, evidence date, headline, meaning, and action before secondary detail. The project selector remains touch-safe and the complete textual equivalent stacks below.

Semantic landmarks, one `h1`, ordered headings, meaningful scene alt text, decorative isolation, visible focus, labelled tabs and panels, roving keyboard focus, complete textual equivalents, written evidence statuses, direct repository links, reduced-motion equivalence, and accessible mobile navigation are included.

## Known limitations

- Repository metadata is a 2026-07-14 snapshot and may change after review.
- Compatibility language is limited to repository descriptions and the cited PaystackOJS README; no universal matrix is inferred.
- Artwork requires Kaduna cultural/architectural, anatomy, tool, component, rail-geometry, and crop review.
- The yard is illustrative and not a real Airix or partner facility.
- No separable supporting elements or motion layers were generated.
- Passing checks is not visual, technical-product, cultural, factual, or owner approval.
